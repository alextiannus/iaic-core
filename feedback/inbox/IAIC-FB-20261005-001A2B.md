# Standardize agent-discovered issues and trusted reporter follow-up

## Outcome needed

Define a reusable Core contract for bounded issue observations from User Assistant AI and Business AI, while requiring trusted-resolution follow-up to the original user for user-reported issues.

## Observed behavior or practice

12Eat practice identified that authorized User Assistant AI and Business AI should be able to report candidate issues from bounded runtime facts without impersonating an end user. It also identified that an end-user report should retain its original reporter identity through trusted resolution and separate notification admission, delivery, and read states. This is confirmed design feedback; the current implementation state for the complete reusable contract is Not verified.

## Why this belongs in Core

Issue provenance, an observation-to-support contract, trusted resolution gates, and reporter follow-up are cross-application responsibilities. Keeping this contract in Core prevents each application from creating incompatible prompts, issue source semantics, and notification completion claims.

## Expected reusable behavior

Core should accept bounded candidate observations with explicit source kinds for end users, User Assistant AI, Business AI, and trusted system observers. Agent-detected candidates must remain distinguishable from user reports and unverified conclusions. For an end-user report, trusted repair evidence should preserve the same issue identity and produce separately recorded notification admission, delivery, and read facts for the original reporter.

## Current application workaround

The historical Obsidian note reports that 12Eat uses existing Support tools and application-owned identity, evidence, and notification adapters. Whether the current application implements the complete agent-observation and follow-up contract described by this record is Not verified.

## Core decision and rationale

Accepted: reusable provenance, trusted observation admission and original-reporter follow-up compose existing Support and Notifications. The task is authorized by the user request to implement the latest 12Eat feedback. Implementation is bounded to this record; the larger historical conversational/repair-agent design remains separate. ## Implementation and release evidence

Original issue and reporter identity are preserved through reopen. The read-evidence and per-consumer retry tables are additive.
