# Task handoffs

`HandoffStore` owns only handoff contracts, child receipts and model-admission counters. `TaskHandoffs` composes injected current Task/Artifact/identity/capability ports. The existing `AgentRuntime` remains the only executor. Import from the Core root or `handoffs/*`. There is no UI, second task engine or protocol-specific server.

The first implementation is an explicit host/owner-mediated handoff from one parent waiting for input to one child under the same application/subject. The target is another registered Agent capability. Parent and child must use the same Runtime release. Nested handoffs are rejected. Parents waiting on uncertain effects, interrupted execution or exhausted limits must be reconciled through their original controls, not bypassed by a child. The host controls actual Agent identity binding and per-Agent model configuration through the existing Runtime ports; a capability name alone does not provision an independent service principal.

`create(actor,{requestKey,parentTaskId,capability,goal,successCriteria,tools,artifacts?,requiredArtifacts?,deadlineAt,maxModelCalls})` validates an explicit subset of the parent task and target tools, pins input Artifact references and persists immutable terms. The target receives the new goal, criteria and references, without copying parent transcripts. Parent Mandate references are preserved. Success criteria are presented to the child; the target's trusted output verifier still decides completion. A string criterion is not itself an executable semantic verifier.

Required host ports: `resolveScope`, `restoreActor`, `authorize`, `readTask`, `readTaskState`, `admitTask`, `findTask`, `cancelTask`, `capabilityFor`, `readArtifact`, and `attenuateInput`. Scope is trusted `applicationId/subjectId`; model arguments cannot choose a different owner or payer. Task reads must enforce current access and return durable Task fields/history through the existing public interface. Use `Runtime.state`, or a host state port enforcing current account ownership, for lifecycle checks without results/transcripts; use `Runtime.get` for source-revalidated results. The Core independently rechecks parent capability authority before child execution. Owner-only state/cancel access can remain available after pilot permission is revoked. This keeps cancellation independent of unavailable historical artifacts. Admission uses the existing Dispatcher. `attenuateInput` adapts task-specific source/session/data constraints and may not widen the proposed tools, replace the goal or Mandate, or drop required artifacts. The Runtime also checks the original parent's current `allowCall` rule before each child tool intent, in addition to child/domain authorization. Hosts retain responsibility for resource ACLs and correct attenuation across their domain-specific contracts.

Task admission has the reserved key `iaic-handoff:<id>`. Runtime binds a trusted nullable Task snapshot, and bound Tasks fail closed without the handoff resolver. Lost acknowledgements recover the same key/Task; an occupied key before recorded admission is rejected. No business effect is automatically replayed. Read exposes current child state and still-accessible summary/artifact references, not transcripts. `list` returns at most the50 most recent owner records; it is not a paginated or snapshot listing. Final child success does not certify the parent goal. The owner explicitly reviews and resumes the parent through its existing input/resume controls.

`maxModelCalls` limits **child model admissions**, not provider token counts, platform-issued allowance or money. Each Task/turn admission is persisted before inference, including conservative consumption if a crash or preflight failure prevents the provider call. The same admission is never silently replayed or refunded. Actual provider usage and platform allowance settlement stay in the existing model gateway/ledger under the same owner. This is not a cumulative parent/descendant expense pool. Existing Runtime turn/call/time limits may stop work earlier.

The absolute deadline and parent waiting/current authority are checked before inference and tool intent admission. A parent cannot resume while its child remains active. Parent cancellation closes the handoff and propagates cancellation through the ordinary child Task control. `tick`, called by the existing Runtime before dispatch, reconciles terminal/cancelled parents, expired contracts and lost child receipts. One inaccessible record remains pending without blocking unrelated records; execution checks still prevent its child continuing. Closing a handoff stops future admission, not already admitted model/tool effects; those remain in Task/usage history. Manual `cancel` stops the child handoff and permits separate parent recovery. Failures, waiting results and unknown admission receipts remain inspectable; no automatic semantic retry or failure-takeover policy is supplied.

ImmediToday now composes this service in its separate `ai-native/handoffs.js` adapter and exposes owner-operated HTTP/personal MCP controls. The application limits targets to assistant.run and retains the existing persistent Assistant identity/model/allowance scope; it does not provision another service principal. Internal model-selected delegation and Core MCP control parity remain open. `examples/core-handoffs` proves independent installation and one Runtime with isolated PostgreSQL. `test/iaic-handoffs.integration.test.js` covers context isolation, receipts/restart recovery, current artifact access, scope/domain attenuation, deadline, budget, cancellation and missing resolvers. These deterministic checks are not real-model quality acceptance.

Remaining collaboration work includes broader application/protocol integration, internal model-selected delegation, cross-principal/service ownership, nested delegation, shared expense budgets, richer progress/automatic takeover and A2A. No financial or scheduler failure is resolved by this module.

## Current parent context

`context(actor,parentTaskId,{limit=10})` projects only handoffs linked to the current owned parent, including closed records. It rechecks parent capability access and uses the existing source-revalidated child read plus current Artifact access on every call. It returns null for no records or for a bound child (no inherited parent/sibling context), otherwise `{items,hasMore}`. Each current item carries the handoff ID, delegated goal/criteria, administrative state, child identity/status and accessible successful summary/Artifact references; transcripts and call bodies are omitted. A403/404 while reading a linked result produces only `{id,availability:'unavailable'}`. Other source failures propagate instead of serving cached content. Partial projections are explicit; limit1–20, newest first. This is not an unbounded history or new task authority.

The optional ContextAssembler handoffProvider port consumes this projection. ImmediToday injects it only for unbound assistant.run Tasks, leaving Issue-review and child task contexts separate. A parent can inspect its child's actual artifacts after the normal owner resume without the owner copying summary text or references into a user message. Child success remains source evidence, not parent completion. Owner-arranged handoff and explicit parent continuation still apply; this change does not add internal model-selected delegation, automatic acceptance or cross-principal collaboration. Focused test: test/iaic-handoff-context.integration.test.js. The independent core-handoffs example now also resumes a parent using this current projection.

Child summaries remain historical outputs. Refreshing source access and exact Artifact references does not rerun every native business verifier or rewrite those summaries as current business facts; parents needing current native state must read the relevant domain capability.

Model-initiated delegation uses `validateDelegation`, `createDelegation` and `delegationReceipt` as internal Runtime ports. The reserved `delegation:` request namespace is unavailable to ordinary owner create requests. An internal contract binds its intent ID to the parent's immutable external-result wait; ordinary contracts still require waiting/input. The same source attenuation, target authorization, child admission receipt, deadline, tool restrictions and model admission accounting apply. Child input never inherits a delegation policy.
