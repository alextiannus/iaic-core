# Reconcile an original model request

`UsageReconciler({ledger,authorize,resolveSource}).reconcile(actor,{sourceId})` is the headless administrative contract. Authorization runs before source resolution. The host must resolve a confirmed provider/export record correlated to one original account/request. Caller input selects only sourceId; it cannot choose the recipient, usage, rates, mode or outcome. Core cannot verify the provider's external billing facts itself.

A confirmed source supplies `{sourceId,confirmed:true,scope,requestId,outcome,providerReference,evidence}`. For `outcome=measured`, include normalized `usage` (`input_tokens`, `output_tokens`, optional cached input details and original usage evidence) and `failed` (default true). Rates and SYSTEM_MANAGED/BYOK mode come from the original reservation. Actual measured use is charged once; excess usage remains debt. BYOK settlement records usage but debits zero platform allowance. Provider tokens and issued platform units remain distinct.

For `outcome=not_accepted`, the resolver must also supply `providerAccepted:false` and omit usage. This requires definitive provider non-acceptance evidence, not a timeout, missing usage, HTTP429 alone or absence from a partial log. It releases the original hold without creating a grant or synthetic zero-token settlement. The ordinary ledger.release method still refuses unknown calls; only this confirmed-source path can reconcile them.

`iaic_token_reconciliations` binds sourceId once within the application and one source per original account/request. Binding, settlement/release and receipt commit atomically with the existing account lock. Replays return the original entry; changed owner, request or evidence conflict. Invalid usage rolls back the source binding. Sources must use stable canonical identifiers; two labels invented for one provider fact do not constitute independent evidence. The host remains responsible for correct source correlation.

This operation does not resend inference, execute tools, change models or resume Tasks automatically. After every pending reservation for that Task is resolved, the host may use the existing authorized Task resume API. Version, permission, model, allowance and unknown business-call checks remain in effect. No auto-429 retry, payment workflow or UI is added. Existing production unknown requests remain unresolved until genuine source evidence is available.

ImmediToday offers `scripts/reconcile-assistant-usage.mjs <verified-usage.json>` to DB-authorized operators, with DATABASE_URL and IAIC_USAGE_OPERATOR. The operator label is attribution, not authentication. The file must have kind=verified-provider-usage, confirmed=true, applicationId=immeditoday, employeeId, erpUser, sourceId, requestId, outcome, providerReference, evidenceReference and measured usage or explicit providerAccepted=false. This adapter trusts an operator-verified file; it does not fetch or certify a provider invoice. Do not expose it as a User Assistant tool. Applications can supply their own billing-source adapter and UI.

Migration is additive and included in schema.sql. Old code ignores the new source table while reading the same settled/released call states and entries. Rollback cannot undo a confirmed settlement. Independent consumer: examples/core-usage-reconciliation.
