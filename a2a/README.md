# A2A capability surface

`createCapabilityA2AHandler` is an async factory for a Fetch Request/Response handler using the optional official `@a2a-js/sdk` 1.1 adapter. Install that package to enable this surface; importing other Core modules does not load it. The verified protocol is [A2A 1.0](https://a2a-protocol.org/v1.0.0/specification/), using the official [JavaScript SDK](https://github.com/a2aproject/a2a-js) for JSON-RPC decoding, serialization and error mapping.

Configure `dispatcher`, a single `capability` exposed by the endpoint, `resolveAccess(request)`, and its public `url`. The current resolver returns the same trusted actor and allowed capability names used by HTTP/MCP/SDK. It must authenticate external callers and map them to the existing user/organization identity. Each request and polling step checks current access. Supply the host's actual `securitySchemes` and `securityRequirements` in SDK form for card discovery. The host mounts the handler, provides TLS, body limits and request deadlines.

Discovery is at `/.well-known/agent-card.json` and is authenticated by the same resolver. The endpoint advertises JSONRPC protocolVersion 1.0. Callers send `A2A-Version: 1.0`. `SendMessage` accepts one JSON data part containing the unchanged Capability input and a stable messageId. The dispatcher uses messageId as callId: domain idempotency and the durable task request key are preserved, not replaced by a second replay cache. Deterministic operations return a structured Message; Agent capabilities return their existing durable Task projection. Model billing remains on the existing execution path.

For Agent capabilities, configure `taskBindings: {get, cancel, list, project}`. These names are existing shared capabilities, not direct database access. `get` and `cancel` accept `{id}`. `list` accepts SDK ListTasksRequest filters/pagination and returns `{tasks,nextPageToken,pageSize,totalSize}`; the host must implement its supported paging and filtering explicitly. `project(row)` returns an A2A wire-shaped Task, including stable id/contextId, status, public history/artifact references, and `metadata.iaicCapability`. The latter must match the endpoint's capability. Never put raw model credentials, private input or unrestricted call history into the projection. Follow A2A state semantics: waiting for input/auth is interrupted; an external-result wait is still working. HistoryLength limits apply to SendMessage/GetTask responses.

By default SendMessage waits for a terminal/interrupted task, polling the current shared get capability. `configuration.returnImmediately: true` returns the existing receipt immediately. A disconnected/aborted wait leaves the durable task intact; a wait failure carries taskId and unknown-outcome metadata for reconciliation. CancelTask dispatches the existing cancellation capability with a stable key; it does not undo committed effects. Errors preserve unknown-outcome guidance. Clients must not blindly replay after a lost response.

This is a usable structured-data, polling interface. Streaming, push callbacks, multi-turn message attachment, arbitrary file ingestion and legacy 0.3 negotiation are explicitly unsupported. It does not add a new Runtime, A2A-specific business Skill, cross-principal delegation policy or automatic tool installation. Outbound A2A tool import remains to be supplied. The test example uses the official client, actual PostgreSQL receipts, service reconstruction, cancellation and revocation; it does not demonstrate model quality or complete A2A conformance certification.
