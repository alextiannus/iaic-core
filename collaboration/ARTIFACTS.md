# Artifact sharing and delegated result projection

`DelegationArtifacts({grants, readOwned, authorizeShare, maxBytes})` shares references across an existing grant without copying content into another workspace or changing ownership. It supports bounded text Workspace artifacts identified by exact path, revision and SHA-256 digest. Binary object sharing can use a separate adapter; it is not implicitly converted to text.

The grant's optional `artifacts` list binds issuer-owned input references. Delegate-owned outputs must appear in the successful, exactly bound persistent Task's result.artifacts. A path alone, a latest-version lookup, another task's output, or an output left on a non-successful Task does not authorize sharing.

`read(actor,{grantId,owner:'issuer'|'delegate',reference})` verifies participant access and the active sharing grant, checks reference membership, restores the original owner, and invokes mandatory current host sharing policy. `readOwned(ownerActor,reference)` uses the owner's ordinary scoped storage API; the service verifies the returned reference and content digest before returning bounded content. The response includes grant ID, owner role, exact reference, media type and bytes. Private owner-source metadata is not copied. The host can resolve provenance through the retained owner/reference binding.

`result(actor,grantId)` locates the exact Task through its original admission key and immutable authority digest. It projects lifecycle status, or a successful summary and Artifact references. Current Task/source revalidation and current sharing policy must pass. Each output Artifact is reread and checked before its reference is projected. No transcript, cached Artifact body, input, error body or provider payload is returned. A summary is historical verified Task output; it is not automatically refreshed business truth.

The host `authorizeShare` port receives `action:'artifact'` with ownerActor, recipientActor, grant, owner role and reference; `action:'result'` receives ownerActor, recipientActor, grant and taskId. It must independently approve result sharing even when an output has no Artifact references. Grant participation alone does not opt the application into sharing. Current data-owner restrictions belong in this port and readOwned. Both are trusted application adapters, not model choices.

Grant revocation denies later shared reads and projections, including ContextAssembler revalidation. The admission deadline alone does not hide an already completed result, because results may be consumed after execution has ended. Owners keep their own ordinary workspace access. Deleting a source, withdrawing sharing permission, or a digest mismatch denies subsequent reads; this does not erase data already copied by a recipient outside this interface.

`createDelegationArtifactCapabilities({artifacts})` exports collaboration.artifact.read and collaboration.task.result through the same CapabilityDispatcher, with live source revalidation. These capabilities can be used through the normal SDK/HTTP/MCP surfaces or selected as Agent tools. Add them explicitly to an application's capabilities and to approved Agent/grant tool scopes. No UI or secondary artifact store is imposed.

Real PostgreSQL tests cover original ownership/version continuity, current policy and grant revocation, source deletion, corrupted content and out-of-grant references. The persistent Task integration uses the actual AgentRuntime, Grant, shared payer budget and Workspace to create an output as the delegate, then lets the issuer read its approved reference. Other isolated tests use a fixture Task port; those do not independently establish Task recovery. All current samples remain deterministic-model evidence.

DelegatedTasks supplies Runtime-driven cancellation sweeps. Parent/child scheduling and automatic failed-child takeover remain separate collaboration work. Existing Artifact retention, correction/deletion propagation outside this sharing interface and full real-model acceptance also remain incomplete.
