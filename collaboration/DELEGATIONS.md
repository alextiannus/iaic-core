# Cross-principal Runtime delegation

`CrossPrincipalDelegations({authority, artifacts, resolvePlan, readArtifact})` implements the existing AgentRuntime `handoffs` port for cross-principal Tasks. `authority` is DelegatedTasks with DelegationParents configured; `artifacts` is DelegationArtifacts. Pass the bridge as Runtime.handoffs, the same authority as Runtime.authority, and connect ContextAssembler.handoffProvider to `({actor,task}) => bridge.context(actor,task.id)`. Keep ticking the original Runtime; no second queue or executor is introduced.

A parent enables its existing input.delegation policy with a target capability, maxModelCalls and timeoutMs. Its model proposes a goal, success criteria, reduced tools and optional exact input/required output Artifact references. The trusted resolvePlan port receives `{actor,parent,request,deadlineAt,input}` and returns `{input,delegate,payer,constraints,budgetId,maxToolCalls}`. The returned input must preserve the proposed goal, tool list, requiredArtifacts, Mandate and inputArtifacts; it may add domain selectors needed by the target contract. Model output cannot select the payer, executor or permission policy. Both principals and the parent domain remain checked by DelegatedTasks and DelegationParents.

Initialize the grant schema and payer ledger/budget first. The budget must allow delegationExecutorKey(delegate). The host owns current principal restoration, domain authorization, sharing policy and model credential selection. A common expense pool for parent and child requires the host to bind both gateways to that payer budget; this bridge only supplies the child binding. Input Artifact references remain in the issuer's Workspace; applications can register the existing shared Artifact read capability and pass the grant reference through their trusted input selectors when child reads are needed.

The bridge validates the proposal before Runtime persists its immutable delegation intent. On a later tick it binds a grant to that exact parent waiting event, then admits the child through the shared Dispatcher with the reserved grant key. Reconstruction after intent persistence or child submission finds the original grant/Task. Once issued, the plan is immutable; later host configuration does not silently change it. Current authorization still applies. The existing grant sweep cancels unfinished revoked/expired children and children whose parent closes.

The parent receives the original child's terminal lifecycle receipt and resumes its original goal. Its context gets a fresh, bounded result/Artifact projection with current sharing and source checks, never the child's transcript. Revoked sharing yields an unavailable result rather than cached content. Successful child work does not bypass the parent's independent verifier. A cancelled child also resumes its parent: the parent can continue under its own authority, inspect original effects, or ask for missing input. Cancellation is not proof that an earlier external effect did not happen; neither this bridge nor its receipt retries such effects automatically.

This adapter is an alternative to the existing same-owner TaskHandoffs port. It explicitly rejects those reserved keys and bound Tasks; simultaneous routing of both adapters is not included. Nested children are disabled. Function/tool grants currently require a nonempty tool scope. Deadline enforcement remains admission and Runtime-tick based rather than provider hard kill.

Integration evidence uses real PostgreSQL, two principals, actual Workspace/effect writes and deterministic models. It reconstructs services after parent intent and child completion, proves exact receipt reuse and artifact continuation, and exercises cancelled-child takeover with one independently verified effect. It does not claim real-model quality, remote A2A orchestration, process-crash recovery in this new bridge, or complete failed/unknown-effect takeover acceptance.
