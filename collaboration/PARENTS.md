# Parent authority binding

`DelegationParents({grants,allowLink})` is an optional parent-control adapter for DelegatedTasks. Supply it as `parents` when constructing DelegatedTasks, or assign it during trusted application composition before admitting linked work.

An approved grant may include `task.parent: {taskId,version,waitingSeq,delegationId?}`. Obtain the reference from the issuer-owned parent Task's current `TaskStore.controlState`. This owner-scoped port returns the control fields and latest durable event sequence without loading tool bodies or transcripts. `waitingSeq` binds the exact current waiting episode; timestamps are not used as the equality fence. An old grant cannot become valid again when the same parent later returns to waiting, even if timestamps coincide.

The parent must be waiting/input for an explicit owner-mediated link, or waiting/external_result with the exact unreceived delegationId for a Runtime delegation intent. Parent and child use the same Runtime release. Nested handoffs/authority-bound parents are currently rejected. The issuer must own the parent, retain current Agent authority, and explicitly permit all grant tools through the parent's own allowedTools and declared tool list.

The mandatory `allowLink({actor,parent,terms})` port checks application-owned context/resource attenuation. It must constrain child input/artifact/knowledge/session choices according to the parent; generic Core cannot interpret each application's domain input fields. On each child action, the parent's original allowCall rule is also checked with the parent input and issuer actor. The original Runtime also rechecks the parent Mandate and persistent Agent binding, including tool-level Mandate rules. These checks complement the child's own grant and capability authorization, not replace them.

DelegatedTasks checks the parent before binding, every inference and each tool/context/read-poll admission. Missing parent adapters fail closed. Runtime cancellation sweeps also stop unfinished children when their original parent waiting episode closes or the parent disappears. Explicit grant revocation and deadline cancellation do not depend on being able to read an otherwise unavailable parent.

This adapter does not automatically create a grant, select a delegate, attach results to the parent's model context or resume the parent. Existing Runtime delegation intents/receipt controls remain the continuation authority. Automatic cross-principal parent/child orchestration and failed-child takeover still need their integration bridge. Applications can already create an explicit grant from an approved parent wait and read the child result through DelegationArtifacts. Do not automatically replay a failed child's unknown external effects.

The real PostgreSQL/Runtime tests verify parent domain narrowing, pause and recovery when that domain rule changes, parent cancellation propagation, missing-resolver denial and rejection of grants from an earlier waiting episode. Fixtures choose their next action from the observed persisted output, instead of assuming that a blocked first action succeeded. They remain deterministic-model evidence.
