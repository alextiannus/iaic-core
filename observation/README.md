# Release observation and protective rollback

`ReleaseObservation` keeps operational evidence separate from an Agent's own output. The host supplies current authorization, a trusted `resolveSource(sourceId,{actor,sourceScope})`, a clock, immutable channel policies, the release service and a replaceable observation store. `PostgresObservationStore` provides append-once source records and content-addressed assessment snapshots. `createObservationCapabilities` exposes record/assess/protect through ordinary shared dispatch.

The public record input is only a source ID. Its resolver must return confirmed evidence for the configured sourceScope, with a stable sourceId and `record`: releaseId, manifestDigest, observedAt, success, durationMs, toolErrors, providerTokens and platformUnits. Optional cost is `{currency,minorUnits}`. Counts and money use nonnegative integer strings where specified; measured duration uses finite milliseconds. Provider tokens, platform allowance and actual currency are not substituted for one another. The adapter stores these metrics and source references, not copied messages, secrets or raw provider responses. Corrections require a new source revision/ID; prior evidence is immutable. Finished work can be recorded after its release stops.

## Policy and snapshots

A channel policy supplies revision, fallbackId, minSamples, maxErrorRate, maxMeanLatencyMs, windowMs and maxAssessmentAgeMs (no greater than windowMs). The observation window is chosen by the host's fixed lookback policy and current clock, not caller-selected dates. Optional maxCostMinor requires a currency. Cost thresholds require complete, same-currency evidence; missing or mixed money is not treated as zero. Fewer than minSamples or a truncated window (10,000 records) is incomplete and cannot trigger rollback. These conditions do not certify healthy behavior; the host should handle missing telemetry separately.

Assess checks the release binding and preserves metric aggregates, the policy digest, source IDs/digest, fixed time window, violations and completeness. It does not change a release. Policies are copied at construction; no Agent capability edits thresholds or fallbacks. Error rate and mean latency are basic controls, not an exhaustive statistical quality evaluation. The host owns representative collection, independent outcome grading and policy calibration.

Protect requires a complete failing snapshot, the same current policy and a fresh assessment. It calls ReleaseManager.rollback with the host-pinned fallback and the exact expected channel revision. The release store atomically verifies candidate/fallback bindings, disables the candidate, changes the channel and appends actor/evidence history. A concurrent promotion or channel edit fails the compare-and-swap before either stop or rollback occurs. The fallback must already be a registered, enabled release; candidate registration retains the existing capability/regression evaluation gate.

Current released-code execution checks stopped bindings, so subsequent work on the stopped candidate is rejected and new resolution selects the fallback. The candidate is disabled across its release namespace; only the specified channel is rewired, so other channels using it may also need their own fallback. Existing committed effects are not undone. Hosts must integrate these checks in each execution path; stopping a registry entry does not itself shut down an arbitrary cloud service.

## Default Runtime evidence source

`createTaskObservationSource({tasks,ledger,resolveContext,resolveRelease})` adapts finished succeeded/failed Tasks using module ports. The trusted context resolver maps a source ID to taskId, authenticated owner actor and billingScope. The release resolver must use the task's immutable admission binding, never the latest channel. `TokenLedger.taskUsage(scope,taskId)` independently aggregates settled provider tokens and charged platform units; pending usage prevents confirmation. The source checks measurable-call coverage and rejects model work with no ledger records. It is for Runtime paths that use the metered gateway for every model; unmetered/mixed providers require another evidence adapter.

Task duration is end-to-end created-to-finished time, including queueing and waits. Tool errors come from persisted call states. It emits references/metrics only, not Task input, Artifact content or Session history. Monetary cost is deliberately absent because the allowance ledger does not own currency prices; a trusted financial cost adapter can enrich a source when needed. Hosts schedule source collection and assessment/protection using their existing event/worker mechanism. This module does not add a mandatory background engine.

## Verification and remaining scope

The release example uses actual Docker execution duration and a deliberately impossible zero-millisecond fixture budget to trigger the guard. It proves stale channel revisions do not stop a candidate, an accepted rollback stops its original code binding, and the fallback executes. It is a deterministic policy-path test, not a production latency recommendation or regression study. The persistent Agent template also reads its finished task through the default source and ledger. PostgreSQL checks cover immutable source IDs, insufficient samples, stale snapshots, mixed currencies and distinct provider-token/platform-unit accounting.

Cloud service deployment adapters, provider telemetry ingestion, full statistical monitoring, automated collection scheduling and end-to-end real-model acceptance remain unfinished. Repository CI and these fixtures do not establish the full Note 30 objective.
