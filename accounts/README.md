# Accounts, organizations and memberships

This independent headless module supplies a default PostgreSQL directory and a replaceable service port. It owns generic account/organization state and membership records, not application business facts, login screens, passwords or business permissions. Human, service and Agent principals can all be mapped to accounts; there is no mandatory role taxonomy.

`PostgresAccountStore({pool, namespace})` provides `initialize`, `get(kind,id)`, `put(kind,id,value)`, `membership(organizationId,accountId)`, `putMembership(...)`, `listMembers(organizationId,page)`, `listMemberships(accountId,page)` and `access(accountId,organizationId?)`. Kinds are `account` and `organization`. Updates require `expectedRevision`; zero creates, a positive revision replaces the state/profile or membership state/roles. They are replacements, not patches. Stale writes return 409. Account and organization states are `active`/`suspended`; membership states are `active`/`removed`. Removing membership retains a revisioned record and does not delete domain data.

`AccountDirectory({store, namespace, resolveIdentity, authorize})` works with this default or an existing-system adapter implementing those methods. The default store namespace must match the service namespace; an external adapter must enforce equivalent application isolation. Store methods are trusted administrative ports; bootstrap the first account/organization/membership through trusted provisioning. Do not expose raw store writes as unauthenticated endpoints.

`actor(credentialContext)` calls the host's `resolveIdentity`, which authenticates existing credentials and returns `{accountId, organizationId?}`. It verifies current account/organization/membership state and creates an actor scoped by application, organization and account. No credentials are copied into the actor. Organization-shared Agent resources remain an explicit host scope choice.

`current(actor)` re-reads current active state. Each service read/write calls it and then `authorize({actor,current,action,target})`. Policy receives current membership roles, not cached role claims. Labels do not grant permissions by themselves. Map trusted request identity to `actor`; never accept a serialized actor from model arguments or an unverified request. Wire `current` into Capability authorization and durable Runtime current-access checks to stop later operations after revocation. A past check is not a lease granting future access.

Service operations mirror storage, adding actor as the first argument. Policy action names are `account.read/write`, `organization.read/write`, `membership.read/write/list/listForAccount`. Applications define who can provision/manage organizations and assign role labels. Profiles are ordinary JSON metadata; credential secrets belong in the credential/Vault integration. The module has no UI and does not enforce industry roles, owner count, invitation workflows or billing plans.

`access` joins current account, organization and membership in a single database snapshot. It does not make a later external domain write atomic with revocation; the domain service must enforce its own authoritative constraints. Suspension prevents future checked operations; it does not reverse completed effects or automatically cancel existing Tasks. Hard deletion, audit retention, SSO providers, subscriptions and payment/refund services are separate lifecycle/integration work.

See `examples/core-accounts` for default persistence and authenticated Capability composition, and `test/iaic-accounts.integration.test.js` for isolation, concurrency, instance reconstruction, current revocation and existing-system adapter substitution.

`createAccountCapabilities({directory, prefix?})` exports eight schema-defined operations for the same Dispatcher, HTTP, MCP and Runtime surfaces. Current reads can be revalidated before reuse in model history. Writes require a stable call ID but are declared `never-replay`: optimistic revision checking is not a complete operation-idempotency ledger. After an unknown write, reconcile the current record before deciding on another mutation.
