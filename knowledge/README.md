# Knowledge

Sourced reference material, separate from user memory, working artifacts, executable Skills and current authoritative business records. No UI, embeddings, crawler, installation framework or new Runtime.

`KnowledgeCatalog({store, authorize, now?, maxBytes?})` exposes `search(actor,{query?,after?,limit?})`, `read(actor,{id,expectedVersion?})` and `revalidate(actor,{id,version})`. `authorize(actor, metadata)` is required and evaluated on every read/search, before body retrieval. Applications own identity, tenancy, ACL and trust policy; metadata is not itself a grant. Expired entries are unavailable. Denied and missing IDs both return 404. Search is a bounded, case-insensitive literal substring scan; omitting query browses metadata. Cursor is the last visible ID, limit defaults to 20 (max 50).

Search returns title, description, source, expiry and `{id,version}` references, without body or adapter paths. Read returns text with the same metadata. Version hashes metadata, provenance/access fields and text. A changed expected version returns 409; consumers rediscover explicitly. Historical knowledge results are revalidated and replaced by an unavailable reference after changes, deletion, expiry or revoked access. Persisted audit is retained; this is context invalidation, not guaranteed removal of all previously derived artifacts.

Store port: `list()` returns registered metadata; `describe(id)` returns the current metadata or 404; `read(id)` returns UTF-8 text or 404. Metadata requires id, title, description and source `{kind,reference}`; optional expiresAt and application-specific ACL fields. Stores must return a coherent current metadata/content view; remote/database adapters should read from a single snapshot. The catalog supports up to 1,000 records and 60 KB per body by default. It deliberately errors on unsupported size rather than silently dropping content.

`FileKnowledgeStore({root,entries,maxBytes?})` is the first adapter. Trusted developers register `{id,file,title,description,source,expiresAt?,...policyMetadata}`. Paths stay inside the registered root and are never supplied by a model. Content updates, corrections and withdrawal are application release changes; this adapter is read-only to users/Agents. Use immutable release files while workers run. This file adapter has no runtime authoring API; optional versioned text ingestion is now described in INGESTION.md. Semantic/vector retrieval and historical-version archive remain unfinished. Replace the store for those lifecycle needs; do not make Knowledge own business tables.

`knowledgeTools` exposes the same search/read contract through MCP or other adapters. `createKnowledgeCapabilities` adds dispatcher authorization and historical revalidation. `createAssistantTaskCapabilities({knowledge,...})` includes these read-only tools when a catalog is supplied. Applications decide reference quality, what constitutes an accepted answer and whether a live business lookup is required. Knowledge text never expands an Agent's permissions.

Validation: `node --test test/iaic-knowledge.test.js`; the PostgreSQL Assistant integration suite exercises the shared task loop. The independent package example checks this module without ERP or application source imports.

## Persistent source adapter

`PostgresKnowledgeStore({pool, namespace, maxBytes?})` stores one current version per ID in its own table. A trusted host chooses the namespace and authorizes ingestion; model input must not select a namespace or supply trusted policy metadata. Call `initialize()` before use. `put({id,title,description,source,text,expiresAt?,policy?,expectedRevision})` creates at revision 0 or replaces the exact current revision. Concurrent or stale writers get 409. `withdraw({id,expectedRevision})` erases current content/metadata and retains an incremented tombstone; `state(id)` returns that revision and withdrawn flag. Restoring requires the tombstone revision and explicit sourced content, never revision 0. No historical body archive or source truth guarantee.

`list/describe/read` implement the existing store port. `snapshot(id)` returns `{entry,text}` from one SQL statement; Catalog uses it when supplied, so authorization, source/version and body refer to the same row snapshot. The file adapter still requires immutable release files. Namespace separation is storage routing, not actor authorization; the injected Catalog authorizer interprets `entry.policy`. Policy and source changes invalidate references along with text. Reads still enforce expiry and the existing bounded search/content limits.

KnowledgeIngestion now supplies authorized source resolution, bounded text splitting and atomic source replacement/withdrawal through a separate default Catalog adapter. Host extraction/source verification, subscription/crawling, vector retrieval and broader deletion propagation remain integrations or later capabilities; UI belongs to applications. Raw Task/Session/audit copies are not globally erased. ImmediToday retains its default file references; `applicationKnowledge` accepts an optional initialized store for host composition. The new adapter does not silently migrate or overwrite existing knowledge. Rolling a dynamic adapter back to a Catalog without the snapshot port loses the coherent-read guarantee; use compatible readers.

Tests: `test/iaic-persistent-knowledge.integration.test.js` covers persistence, concurrent corrections, namespaces, policy changes, withdrawal/restoration and Context history invalidation. The independently installed core-knowledge example exercises PostgreSQL persistence and withdrawal alongside the file adapter.


See INGESTION.md for the independent versioned-source ingestion service and PostgresIngestedKnowledgeStore, including unchanged replay, source revisions, chunk references, limits and withdrawal.
