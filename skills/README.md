# Skills module

`SkillCatalog({root, entries, maxBytes})` loads application-registered filesystem packages. `list()` returns name, applicability description, format and the SHA-256 of the entry document, without its body. `read(id, {resource, expectedVersion, expectedResourceVersion})` loads that entry or a relative package resource. Optional `expectedVersion` rejects a changed entry document with 409; rediscover before choosing its new revision. Returned `version` hashes the loaded file; `skillVersion` hashes SKILL.md. These are file hashes, not a whole-package release lock: applications must pin immutable packages and include referenced resources in their task implementation revision.

Standard YAML frontmatter supports name, description, license, compatibility, metadata and allowed-tools according to https://agentskills.io/specification. Name must match its directory; metadata values are strings. Duplicate keys, invalid types, aliases and unknown YAML tags are rejected. Legacy Markdown-only packages retain heading/paragraph discovery. Unknown extension fields are ignored. A malformed registered package fails discovery explicitly rather than disappearing silently.

The application supplies installed entries and retains authorization. `allowed-tools` is descriptive only: Core does not grant tools, execute scripts, install packages, resolve compatibility or bypass capability authorization. Discovery reads bounded entry documents; related resources load on demand within the registered package. No UI or marketplace is included.

Dependencies: filesystem, Node crypto/path and YAML parser. Focused verification: `node --test test/iaic-skill-catalog.test.js` from the host repository. The host owns HTTP/MCP capability bindings; tests need no application server or ERP.

Resource reads optionally accept `expectedResourceVersion`, the `version` returned by a previous read. A mismatch returns 409 even when SKILL.md is unchanged. `expectedVersion` continues to pin SKILL.md independently; supply both to check both files. Assistant and Issue capability adapters expose the same option, including history revalidation. Omit the resource pin for an explicit current-version read. No historical file storage or whole-package lock is implied.

`skillOperations(catalog)` owns the shared list/read schemas, output contracts and execution functions. Assistant and Issue capability definitions consume them; the Issue adapter adds its existing business-scope context and authorization. ImmediToday exports the exact Assistant dispatcher capabilities as `my_list_assistant_skills` / `my_read_assistant_skill` and GET `/api/assistant-skills` (no id lists metadata; id reads with optional resource and version conditions). HTTP query fields are schema-checked, including unknown/duplicate fields. These are read-only projections with the same current pilot/account access checks, not installation or script execution endpoints. Known missing resources return 404, out-of-package reads 403, invalid resource syntax 400 and size limits 413.

Application/protocol integration tests live in `test/ai-native-skill-surfaces.integration.test.js`; Core catalog tests remain independent. Direct discovery/read does not invoke a model or debit platform inference allowance. No Skill authoring UI, marketplace, package release lock or catalog pagination is added.

Optional `selectEntries(context)` selects a subset of registered entries at each discovery/read. The host resolves its own current actor settings; Core adds no settings table or UI. Return unique registered IDs (an empty array disables all). Invalid selections fail explicitly and cannot register arbitrary paths. `list(context)` and `read(id, options, context)` pass trusted execution context separately from model input. Use `context.actor` for identity; other optional fields vary by execution surface. The default remains the full static catalog.

Shared operations, Assistant/Issue adapters, progressive context discovery and history revalidation forward the current actor. Removing a selection prevents subsequent reads and historical body refresh (404); Runtime follows its ordinary error/wait behavior rather than silently retaining the stale Skill. This does not remove text already copied into a goal, session or audit. Selection does not grant tool permissions. Hosts can inject a catalog implementing the same list/read port; application-specific selection persistence remains outside Core. Focused test: `test/iaic-scoped-skills.test.js`.

When ContextAssembler has a catalog, eager Skill bodies also load through its current selection. The legacy no-catalog filesystem path remains an explicitly host-configured static instruction path and offers no per-actor selection.
